# Side A — customer walkthrough

Use **Sample Set 02 — Side A** for the complete scenario, or **SA-02 / Web**, **SA-02 / Mobile** and **SA-02 / Desktop** for an individual example.

## Try the journey

1. On the website, filter the programme to Jazz & soul. Open The slow side, choose a fictional guest name and party size, and create a demo ticket. Reload and open Your demo booking to see local persistence. Download the ticket, then cancel the demo booking. Save a record on the listening shelf.
2. In the iPhone app, explore Discover, open My tickets, and save a record in My crate. Add a ticket for a different session, export a backup and restore it through Import backup. Cancel the extra demo ticket when done.
3. In The Door, choose a session. Search for Jamie, check the party in and observe the arrived count. Edit the party or move it to another session. Try adding more than the session can hold: the capacity check rejects it. Export before using Reset demo or replacing data with an import.

These are three independent local examples, not a connected reservation system. Use fictional information only.

## Decisions for a commissioned version

| Decision | Options to discuss |
| --- | --- |
| Functional starting point | Venue discovery and booking; customer tickets and favorites; staff guest-list operations; a combination |
| Visual direction | Night Shift from any SA-02 platform, Fieldwork from CF-01, or a tailored direction |
| Platforms | Responsive web, iPhone, Android, desktop; only the platforms agreed in the scope |
| Accounts and ownership | Client-owned domain, hosting, data and publishing accounts, managed by HensTek as agreed |
| Booking rules | Session capacity, waitlists, timed holds, cancellations, refunds, accessibility requirements |
| Payments | Agreed processor, pricing/tax treatment, receipt and refund flows; no payment integration is included in this sample |
| Staff operations | Permissions, check-in, audit trail, inventory and exports |
| Data | Shared backend, offline use, retention, deletion and recovery responsibilities |
| Handoff | Source, deployment access, runbook, training and any separately agreed support |

Reference functionality and style separately: “SA-02 / Desktop guest-list workflow with CF-01 / Web colors.” The inquiry form records both. Sample selection is a scoping aid, not a fixed-price promise. Agree deliverables, acceptance criteria, milestones and ownership in the project agreement before production work.
